# 生信工具选型指南

## 适用场景

- 用户只提出了分析目标或结果需求，未指明具体使用哪些工具；
- 参考方案省略了必要前置/衔接步骤的工具；
- 用户或参考方案中指定的工具违反平台约束，需要选择兼容的命令行替代工具。

## 平台硬性约束（不得选用）

以下类型的工具**不能**选入分析工作流：

1. **需要图形界面（GUI）的工具**。
2. **闭源、缺乏公开容器/Bioconda 生态，或强耦合黑盒多步调度器、难以拆入节点工作流的一体化套件**（例如 CellRanger）。
3. **直接照搬第三方流水线的现成脚本**（R/Python/Bash/Perl）：优先选用独立的命令行（CLI）生信工具；仅当没有专门 CLI 工具、且只是为下游 CLI 工具准备输入的简单中间转换时，在计划中描述转换目标即可，由后续构建智能体决定用 Bash、Python 还是平台内置功能实现。

## 候选工具选型优先级

当多个命令行工具都能满足某一步的分析需求时，按以下顺序权衡选择：

1. **更好的准确性或运行性能**：优先选择结果精度更高、算法更可靠或计算资源效率更好的工具。
2. **较新发布或持续维护**：优先选择近期仍在积极维护、适配当前数据格式和主流标准的工具。
3. **更广的兼容性与社区采用度**：优先选择主流、易于容器化或通过 Bioconda 获取的命令行工具；同等适用时，优先选择通过显式文件参数输入输出、无需特定目录层级或命名约定的模块化 CLI 工具，以减少前置目录整理与文件拷贝开销。

## 查证原则

优先依靠自身生物信息学专业知识做选型决策；只有对冷门领域、新型测序平台或工具兼容性确实拿不准时，才使用 `web_run` 检索核实。
